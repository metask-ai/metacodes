# Core / AgentLoop 文件修改结果可观测能力

## 背景

上层需要向消费方展示会话中由文件修改工具实际产生的修改。文件预览、会话聚合和界面展示由上层负责。

## 当前缺口

- `file_refs` 只能说明涉及了哪些文件，不能说明具体改了什么。
- `tool_result.content` 可能包含 `gitDiff` 等工具私有数据，但其格式不是稳定公共契约。
- 上层因此无法可靠获取工具实际产生的文件修改。

## 所需能力

Core / AgentLoop 需要通过稳定、受支持的方式，对上层提供文件修改工具实际产生的修改结果。

范围包括：

- `Write`、`Edit`、`NotebookEdit`、`ApplyPatch` 等文件修改工具。
- 文件新增、修改、删除、移动及单次多文件修改。
- Agent、Skill 等子执行产生的文件修改。
- 无实际变化、失败、拒绝、部分完成及结果不完整等状态。

## 验收标准

真实 Run 执行后，上层能够获取并展示每个文件的实际修改，无需解析 `tool_result.content` 中的工具私有格式。

## 不在范围内

- 文件预览、会话聚合和 UI 展示。
- 评论、审批、接受或拒绝等评审能力。
- Bash 或任意终端命令造成的文件系统变化。
- 具体字段、事件或协议设计，由 Core / AgentLoop 维护方决定。
- AgentCore 封装及 Desktop 消费逻辑。
